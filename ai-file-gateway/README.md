# AI File Gateway

An AI-powered document gateway on Cloudflare Workers (Free plan). Upload PDF, XLSX, CSV, DOCX,
PPTX, TXT, or Markdown files and interact with them via a REST API or a remote MCP server:
search, ask questions (RAG), summarize, translate, and compare — all while minimizing LLM token
usage.

```
Upload → GitHub storage → text/markdown extraction → chunking → embeddings → Vectorize → metadata + token count (D1)
Question → retrieve relevant chunks only (Vectorize) → minimal context to LLM → answer with source references
```

Extraction/chunking/embeddings are cached by content hash (Workers KV + a D1 lookup), so
re-uploading a byte-identical file never reprocesses it.

## Why GitHub instead of R2

Original files are stored in this repo's `storage/` directory via the GitHub Contents API,
not Cloudflare R2 — a deliberate choice to avoid Cloudflare paid object storage. Everything else
(D1, KV, Vectorize, Workers AI, Workers) runs on the Free plan.

## Architecture

| Concern | Cloudflare resource | Notes |
|---|---|---|
| File metadata, chunk text | D1 (`ai-file-gateway-db`) | Reused, not created fresh |
| Extraction/chunk cache, dedup | KV (`ai-file-gateway-cache`) | Reused, not created fresh |
| Chunk embeddings, semantic search | Vectorize (`ai-file-gateway-index`) | Created during setup below |
| Embeddings + chat/translation | Workers AI (`@cf/baai/bge-base-en-v1.5`, `@cf/meta/llama-3.1-8b-instruct`) | Free tier: 10k neurons/day |
| Original file bytes | GitHub repo (`storage/` dir) | Not R2 |

## Supported file formats

| Format | Structure preserved |
|---|---|
| PDF | Per-page text, page numbers |
| XLSX | Per-sheet rows as markdown tables, sheet names |
| CSV | Rows as markdown tables |
| DOCX | Paragraphs, headings (via style), lists |
| PPTX | Per-slide text, slide number |
| TXT / MD | Paragraphs |

## How token usage is minimized

- Files are never sent to an LLM whole. Only the top-K relevant chunks retrieved from Vectorize
  are sent for `/ask`, `/search`, `/compare`.
- `/summarize` uses map-reduce over chunk batches (bounded ~3000-token batches), never the whole
  document in one call.
- `/translate` runs chunk-by-chunk, and pre-masks numbers/URLs/emails/formulas/code spans with
  placeholders before translation (restored after) so they're never altered or re-generated by the
  model.
- Re-uploading identical bytes (same SHA-256) skips storage, extraction, chunking, and embedding
  entirely — the existing file record is returned as-is.
- `token_count` per file (extraction/chunking token estimate) is tracked in D1 for visibility.

## REST API

All endpoints except `/health` require `Authorization: Bearer <API_AUTH_TOKEN>`.

| Method | Path | Body |
|---|---|---|
| POST | `/upload` | multipart/form-data, field `file` |
| GET | `/files` | — |
| GET | `/files/:id` | — |
| DELETE | `/files/:id` | — |
| POST | `/search` | `{ query, file_id?, top_k? }` |
| POST | `/ask` | `{ question, file_id? }` |
| POST | `/summarize` | `{ file_id }` |
| POST | `/translate` | `{ file_id, target_language }` |
| POST | `/compare` | `{ file_id_a, file_id_b, focus? }` |

## MCP server

`POST /mcp` — JSON-RPC 2.0 over a single HTTP response per request (MCP Streamable HTTP,
stateless: no session id, no SSE). Requires the same `Authorization: Bearer` header as the REST
API. Supports `initialize`, `tools/list`, `tools/call` with tools: `upload_file`, `list_files`,
`get_file`, `read_file`, `search_files`, `ask_files`, `summarize_file`, `translate_file`,
`compare_files`, `delete_file`.

To connect an MCP client, point it at `https://<your-worker>.workers.dev/mcp` with header
`Authorization: Bearer <API_AUTH_TOKEN>`. Exact syntax depends on the client — most take a URL +
custom headers for a remote HTTP MCP server.

## Setup and deployment

This project was written and tested (type-check + unit tests) outside of a Cloudflare-connected
environment, so the steps below must be run from a machine with `wrangler` installed and logged
in to the Cloudflare account that owns `ai-file-gateway-db` and `ai-file-gateway-cache`. **Run them
in this exact order** — later steps depend on IDs produced by earlier ones.

### 0. Install and authenticate

```bash
npm install
npx wrangler login
```

This opens a Cloudflare consent screen in your browser; approve it. `wrangler` stores the token
locally — no manual API token needed for this path.

### 1. Run the D1 migration (reuses the existing database, does not create a new one)

```bash
npm run db:migrate:remote
```

Confirms `files` and `chunks` tables exist in `ai-file-gateway-db`. Safe to re-run (uses
`CREATE TABLE IF NOT EXISTS`).

### 2. Create the Vectorize index

**Depends on:** nothing before it, but **`wrangler.jsonc` already assumes it exists** as
`ai-file-gateway-index` — do this before step 4 (deploy), or the deploy will fail to bind it.

```bash
npx wrangler vectorize create ai-file-gateway-index --dimensions=768 --metric=cosine
```

768 dimensions matches the `@cf/baai/bge-base-en-v1.5` embedding model configured in
`wrangler.jsonc`'s `vars.EMBED_MODEL`. If you change that model later, delete and recreate the
index with the new model's dimension count — Vectorize indexes are fixed-dimension.

### 3. Set secrets

**Depends on:** nothing technical, but you need two values ready first:

```bash
npx wrangler secret put GITHUB_TOKEN
```
When it prompts (it reads the value from stdin interactively, not as a CLI argument), paste a
**GitHub Personal Access Token** the Worker will use at *runtime* to read/write files in this
repo's `storage/` directory:
- Fine-grained PAT scoped to just this repo, permission **Contents: Read and write**, or
- Classic PAT with the `repo` scope.
This is a *different* credential from whatever you use to `git push` this code — it's baked into
the deployed Worker as a secret and called on every upload/read/delete.

```bash
npx wrangler secret put API_AUTH_TOKEN
```
When it prompts, paste **any long random string you generate yourself** — e.g. output of
`openssl rand -hex 32`. This is the bearer token every REST/MCP request must present. Save it
somewhere; it's not retrievable from Cloudflare after this point (only replaceable by running
this command again).

### 4. Deploy

**Depends on:** steps 1–3 (D1 schema, Vectorize index, and both secrets must all exist first, or
the Worker will error at runtime on first use of the missing piece).

```bash
npx wrangler deploy
```

Note the `https://ai-file-gateway.<your-subdomain>.workers.dev` URL it prints — that's your
deployed base URL for both the REST API and `/mcp`.

### 5. Connect Workers Builds (optional, for auto-deploy on git push)

No CLI equivalent — this is a one-time dashboard step:
1. Push this repo to GitHub (see below).
2. In the Cloudflare dashboard: **Workers & Pages → ai-file-gateway → Settings → Builds** →
   **Connect to Git** → authorize the Cloudflare GitHub App → select this repo → branch `main`.
3. Cloudflare will redeploy automatically on every push to `main` from then on.

### 6. Verify the deploy actually worked

Don't assume success — run these against the URL from step 4:

```bash
# 1. Health check (no auth required) — expect {"ok":true,"service":"ai-file-gateway"}
curl https://ai-file-gateway.<your-subdomain>.workers.dev/health

# 2. Auth is enforced — expect HTTP 401
curl -i https://ai-file-gateway.<your-subdomain>.workers.dev/files

# 3. Authenticated list (should be an empty array on a fresh deploy) — expect {"files":[]}
curl https://ai-file-gateway.<your-subdomain>.workers.dev/files \
  -H "Authorization: Bearer <API_AUTH_TOKEN>"

# 4. Upload a real file — expect HTTP 201 with status "ready" and token_count/chunk_count > 0
curl -i https://ai-file-gateway.<your-subdomain>.workers.dev/upload \
  -H "Authorization: Bearer <API_AUTH_TOKEN>" \
  -F "file=@/path/to/sample.pdf"

# 5. Re-upload the SAME file — expect HTTP 200 (not 201) and "deduped": true, confirming the
#    cache skipped reprocessing
curl -i https://ai-file-gateway.<your-subdomain>.workers.dev/upload \
  -H "Authorization: Bearer <API_AUTH_TOKEN>" \
  -F "file=@/path/to/sample.pdf"

# 6. Ask a question about it — expect an "answer" citing the filename/page
curl https://ai-file-gateway.<your-subdomain>.workers.dev/ask \
  -H "Authorization: Bearer <API_AUTH_TOKEN>" -H "Content-Type: application/json" \
  -d '{"question": "What is this document about?"}'

# 7. MCP endpoint — expect a JSON-RPC result listing all 10 tools
curl https://ai-file-gateway.<your-subdomain>.workers.dev/mcp \
  -H "Authorization: Bearer <API_AUTH_TOKEN>" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

If step 4 comes back with `"status":"failed"` and an `error` field, check `wrangler tail` for the
real exception — the most common causes are the Vectorize index not existing yet (step 2 skipped)
or `GITHUB_TOKEN` lacking write access to this repo (step 3).

## Local development

```bash
npm run db:migrate:local
npx wrangler dev
```

`wrangler dev` uses local Miniflare emulation for D1/KV/Vectorize and proxies real Workers AI
calls — you'll still consume real (free-tier) AI neurons when testing embeddings/chat locally.

## Testing

```bash
npm test        # unit tests: chunking, token estimation, auth, and real extraction of
                 # round-tripped XLSX/DOCX/PPTX fixtures plus TXT/CSV parsing
npm run typecheck
```

PDF extraction (`unpdf`) and the D1/KV/Vectorize/Workers-AI-bound code paths are exercised by the
manual verification steps in section 6 above rather than by unit tests, since they require a real
deployed Worker with live bindings.

## File size limit

20MB per upload by default (`MAX_FILE_SIZE_BYTES` in `wrangler.jsonc`). Adjust and redeploy if you
need a different limit; be mindful of Workers CPU-time limits on the Free plan for very large
PDFs/spreadsheets.
